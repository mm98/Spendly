16a Actions inventory
Every control drawn in the mockups, what it does, and what the user sees afterwards. Compiled by walking each file rather than from memory, so this is what is actually on the pages - including ten controls that had no described behaviour anywhere. Those are resolved at the end, in 16b.
How to read this
"After" is the observable result, because that is what the user judges. toast + Undo means the change applies immediately and is reversible for the toast's life. dialog means it cannot be undone and is confirmed first. Nothing in this document contradicts that pairing - if an action is reversible it does not get a dialog, and if it is not, it does not get a toast.
Global actions live in the shell; page actions do not. Scan receipt and New order live in the sidebar - at the top of the nav when expanded, as the capture tile and + on the collapsed rail - because they belong to the app, not to whatever page is open. The top bar carries search and nothing else. The rule is not that global actions get a special place up there; it is that a page may not put its own actions in the shell at all.

16b Loose ends found, and closed
Ten controls were drawn with no behaviour described anywhere. Each is resolved below - seven by writing down what they do, three by a product answer that is still open and marked as such.
RESOLVED HERE
Export CSV / Export. Appeared on four screens meaning four things. Now one behaviour: it exports the current filter or drill state, never the page and never the whole account, and the button label carries the count ("Export 128 orders"). One row per item line, with order fields repeated, because that is the shape the import reads back - export and import are the same column set, which is what makes a round trip possible.
Save current (saved views). Stores query, facets and sort under a name, listed above the facet rail. It stores the filter, not the result - opening a view re-runs it. Renameable and deletable from the list; a view is never shared, since there is one user.
Archive (vendor). The middle option between keeping and deleting, and the answer to 5c's "no orders in 12 months". Hides the vendor from pickers and facet lists while its orders, totals and history stay exactly as they are. Reversible, so toast + Undo, and archived vendors are reachable behind a filter in the library.
Copy an order (Home and create screen). One action with one set of rules wherever it appears: it opens the 3b dialog, because the order to copy is rarely the newest one. Picking an order applies 8a's duplicate - no date, no status, no attachments - and opens it unsaved, so nothing is created by accident. Hidden when there are no orders. An order's own Duplicate (order page, row menu) still goes straight to the copy, since the source is already chosen.
Reuse mapping. Applies a previous import's column mapping to the newly picked file by matching column names. It always lands on the mapping step with rows pre-filled, never straight on preview: a file with the same headers can still hold different data, and the confirmation step is the point of the flow. Columns that don't match are left unmapped and flagged.
Change password. A dialog - current, new, confirm - not inline fields, so it is never half-filled inside a card that saves other things. Success is a toast; other sessions stay signed in, since signing yourself out of your phone for changing a password on your laptop is a punishment for good hygiene.
Open full size (scan review). Opens the same viewer as 12b, with the receipt as its only file, so the small print can be read without leaving review. Edits in the panel behind it are untouched.
NEEDS A PRODUCT ANSWER See theirs (6d, the two-tab conflict). Recommendation: it opens the other version read-only beside yours, and the only actions are keep-mine and take-theirs. There is no field-level merge - for one user in two tabs that is more machinery than the problem deserves. Duplicate name (6c). A vendor or category name colliding with an existing one. Recommendation: warn, don't block - offer "use the existing one" as the primary and let the duplicate through as secondary, since two vendors can genuinely share a name. Export format. CSV is drawn. Recommendation: CSV only, UTF-8 with BOM so Excel opens Danish characters correctly, and the user's own number format. XLSX only if someone asks.
WHERE THE SIX THAT NEEDED LAYOUT NOW LIVE
Each went to the page that implements it, rather than being drawn a second time here: saved views to Order list 2g, the archived state to the overview's own filter in 5a, the password dialog to Auth, and the duplicate name to the create and rename fields in 5b and 5c, where a name collision blocks the save. Export and the two-tab conflict view were dropped - the first is the one behaviour described above, the second describes a situation the app does not produce.
TWO PATTERNS THE AUDIT CONFIRMED
Every destructive action has exactly one dialog, and every reversible one has exactly one toast. Nothing in the set has both, and nothing has neither. Delete order, bulk delete, merge and discard-scan are dialogs; line delete, status change, category add, archive and import are toasts.
Every "See X" link is a filter handoff, not a new view. See in Statistics, Open in orders, the Needs-a-look rows and the monthly summary rows all carry state into a screen that already exists. No screen in the set is reachable only through one link.
