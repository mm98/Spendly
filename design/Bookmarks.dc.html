22a Bookmarks - all bookmarks
Things the user is interested in buying, each with a link to the shop. A row in the sidebar's Library group, with no tie to orders, totals or the budget. Drawn as cards, the order list card from 2c, with search, a category filter and sort above them. The picture strip opens the shop; the menu edits the bookmark in 22d.
Notes for implementation
The empty picture strip starts its name with what it draws. The strip is still the link to the shop, so its name is "No picture, open at" and the domain: the drawn words first, then where it goes.
The record is a bookmark everywhere. Routes are /bookmarks, /bookmarks/new and /bookmarks/:id/edit; every label, title and button says bookmark.
The card is .sp-record with the sp-record__head--chips variant (categories in the head; see below). A bookmark has exactly one picture, never several. The strip holds that one picture filling its whole width, exactly as an order with one item photo does; there is never a second cell, a divider or a +N count. The form in 22c has one picture slot for the same reason. No picture draws the empty band with No picture, so every card keeps the same height.
The card has two targets. The picture strip at the top is a link to the bookmark's URL, opening in a new tab, so it middle-clicks and copies like one; the link is required and validated on save, so every strip has one to open, including the empty No picture band. Everything below the strip opens the bookmark at /bookmarks/:id/edit, as a click on an order card opens the order. Two controls keep their own action and stop the click from reaching what lies under them: a category chip filters the list by that category, and the menu button over the strip opens the menu. The whole card shows the pointer and the card's hover border, since every part of it does something.
The menu holds what the edit page does: Open at the shop, Edit, Archive, Delete. Open at names the domain, without www.; a long one ends in an ellipsis on one line, the full domain in the item's title. With Archived selected, Archive becomes Unarchive in the same position; it applies at once and the card leaves the archived list. Delete confirms in a popover from the card, the same component the category list uses in 5d.
No checkbox and no bulk bar. There are no bulk actions on bookmarks, so .sp-record__pick is left out rather than shown with nothing behind it.
Cards only. There is no Rows/Cards switch: the picture is what identifies a bookmark.
No price leaves the amount's slot empty - a non-breaking space in .sp-amount, hidden from assistive tech, and .sp-record__foot--single holds that line at the amount's height even if the space is stripped - so the foot keeps the same height on every card and nothing is drawn.
Prices are whole kroner on bookmarks - the card, the summary and the field - since a price is what a shop is asking, not a settled amount. Typed decimals are kept and rounded only for display.
No toolbar row above the cards. A bookmark never reaches a total and has no bulk actions, so there is nothing to sum or act on; the footer states how many are shown. The price is what the shop asked when it was saved, and nothing adds it up.
Search matches the name, the shop and the category names. Sort offers Newest first, Oldest first, Price high to low, Price low to high and Name A - Z; under a price sort, bookmarks with no price go last.
The grid is .sp-cards--fluid, the same as the order cards (2c): as many as fit at --card-min-w or wider, one column below 572px.
Categories sit in the card head, right of the name (sp-record__head--chips), taking at most a third of the width. The first category is a chip and truncates when it must; more show as a static "+N" chip, and the bookmark page lists them all. A bookmark with no category has no chip column. The order card keeps its chip row.
Open / Archived is the vendor list's Active / Archived control. It composes with the search and the category filter.
In the sidebar Bookmarks is a row in the Library group, after Categories. See 10a.

    22b The category filter
    One control beside the search, the sort control's trigger with a different list. It offers the categories that bookmarks use, with how many bookmarks each holds. Picking one narrows the cards and adds a crumb that removes it.
    Notes for implementation
    One category at a time. The filter is a single choice; Any category is the resting value. Picking applies at once, with no Apply button, and closes the list.
    Only categories that have a bookmark are listed, so a pick can never read back zero. Without category appears only while at least one bookmark has none.
    The list is the categories from 5d, the same set orders use. There is no second set of categories for bookmarks; the marks are the categories' own icon and colour.
    A category chip on a card sets this filter. Clicking Lighting on a card gives exactly this screen: the filter reads Lighting, the crumb appears, and the list narrows. Clicking the chip of the category already filtered on does nothing.
    Edit categories is an action, not a value: it closes the list and navigates to Categories in 5d. It sits at the foot of the list, after the separator, so it is never read as a filter value.
    The crumb row is the order list's, from 2b: one crumb per active filter, and Clear all beside them. Removing the crumb sets the filter back to Any category.
    Filters live in the URL, as ?category= next to ?q=, ?sort= and ?archived=, so a filtered list can be linked to and survives a reload. Any change returns to the first page.

    22c New bookmark
    At /bookmarks/new, from New bookmark. The vendor form's page from 5b: fields on the left, the summary in the rail, the sticky bar under the form. Drawn with a category being typed that does not exist yet.
    Notes for implementation
    Link and Name are required; Price, Categories and Picture are optional. Save stays enabled and runs validation, the same as every form here.
    The link comes first because it fills the rest. On leaving the field, a name is taken from the page into an empty Name, and the page's picture is offered in the Picture frame. Neither overwrites anything typed. A pasted link replaces the field and is stripped of tracking parameters.
    A new category is typed, not created first. A name with no match offers Create "Garden" as the list's last option; choosing it or pressing Enter adds the chip. The category is created when the bookmark is saved, with the default icon and the next unused colour, the same way an unknown vendor name on a new order becomes a vendor. Cancelling creates nothing.
    The list is the categories from 5d, the set orders use. A category created here is an ordinary category: it appears on orders, in Statistics and in the Categories list, where it can be renamed or given a limit.
    The picture frame is the file slot from c17, the first field in the card. It has no card of its own: one thumbnail does not need a section. The whole card is the drop target. A picture taken from the page is saved with the bookmark; replacing or removing it before saving discards it.
    Save returns to the list with a toast naming the bookmark: "Palissade Lounge Chair added."

    22d Edit bookmark
    The same page as 22c with the bookmark loaded, at /bookmarks/:id/edit. One thing appears that create does not have: the end-of-life card, with Archive and Delete.
    Notes for implementation
    Archive is the button in the end-of-life card, not a field in the form. It applies at once and returns to the list, where the Archived filter brings the bookmark back. On an archived bookmark the same end-of-life card offers Unarchive instead of Archive. Create has no end-of-life card, since a bookmark being added is one the user wants now.
    Delete is always offered. Nothing points at a bookmark, so removing one takes only the bookmark and its picture. It confirms in the popover from 22a.
    Garden was created by the save in 22c and is now an ordinary category, editable in 5f.
    Dirty tracking, the leave prompt and Save returning to the list behave as on the vendor page in 5c.
