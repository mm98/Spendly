# Brief 32 answers - drafts of orders made by hand, and two faults on Home

1. An order made by hand. Yes, an empty order is a draft until Create or Discard. It starts at the first change, not when the form opens: a character typed in any field, a vendor or category picked, a line added or removed, a file attached. What the form opens with (today's date, the default status) is not a change. An empty form nobody typed in is not kept and leaving it says nothing. Order create 3a, notes group "An order made by hand is a draft from its first change".
2. Leaving it. Yes, as a scan: no question, and the toast "Kept in Drafts" with no Undo. "Leave without saving?" goes for new orders. Editing an order that is already created keeps its unsaved-changes prompt. Reopening is the edit screen as it was left, footer Discard / Create. Discard of a draft with no files is a toast, "Draft discarded" with Undo; one holding a file or photo uses the 6d dialog naming them. Order create 3a notes, Actions inventory.
3. A copy of an order. No, the same rule as an empty order: a draft at its first change. A copy left untouched has lost nothing, since its source is still there, and Drafts does not fill with copies opened by mistake. Its green notice stays on the draft until Create. Order create 3b note, Duplicate and alerts 8a note, Actions inventory.
4. Its row. The picture is the order list's thumbnail cell: the first item photo (a copy carries its lines' photos), the vendor image faded, or the empty square with the image symbol. The name is the vendor, or "New order" before one is chosen. The line under it is the line count, "4 lines" or "No lines yet", and for a copy "4 lines · Copied from 12/08". The day is the day the draft was started; the total is the lines' total, empty with no priced line. It opens in the edit screen. On a phone: "21/08 · 4 lines". The order list shows it as any draft: grey pill, "No reference yet". Home 10a state 5 and notes, Mobile screens 7a note.
5. Card title row on a phone. Fixed in components.css. A text link in a card's head keeps the small button's 34px box and takes the 48px touch target as an invisible area above and below, as the bookmark card's chip does, so every card's head is the same height with or without a link. It applies under .sp-touch and below 640px. Mobile screens 7a note. styles/check.js asserts both rules exist.
6. Long file name. Yes. What is left to check now comes first and the file name last: "2 values need a look · faktura-indbo-4471.pdf", so the cut always falls on the file name. Home 10a rows and note, state 5 shows a long name. styles/check.js flags any one-line meta where a file name comes before more text.
