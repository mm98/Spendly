12a Dark mode — warm dark
Not an inversion. The light theme's identity is warmth — a greige canvas, not grey — so the dark theme is a warm brown-black, and the greens lift rather than darken so they still read as the accent. Every token maps one-to-one, so a component references a role and never a literal.

Four rules behind the mapping: the sidebar does not change, because it was already dark and is the one thing that anchors the two themes. Elevation reverses — a light theme lifts a surface by shadow, a dark theme lifts it by getting lighter, so cards are lighter than the canvas and dialogs lighter again. Shadows stay but only for layering, at half the opacity of the light theme. And the chart ramp keeps its five steps in the same order, lifted: #5d9b76, #7fb392, #a3c9b0, #4a6b57, #39443c.

NOTES FOR IMPLEMENTATION
The sidebar reads no theme token. Its colours are literals, identical in both themes. Do not route it through var(--surface) and friends — a themed sidebar is a sidebar that will drift.
Only the primary action lifts. #1d4d33 has enough contrast against the light canvas but sits too close to #14261c once the page around it is dark, so Scan receipt takes the lifted #5d9b76 and its glyph flips to #14261c. The active row keeps #1f3d2c: it is a state, not an action, and it reads against the sidebar rather than against the page.
The theme toggle at the bottom shows the state it will move to, not the state it is in. In dark mode the row reads Light mode with a sun glyph.
Everything else follows 9a exactly — same rows, same order, same three zones, same 68px collapsed rail, same short-screen behaviour from 9g. This is 9a's markup with two values substituted, and that is the whole difference.
