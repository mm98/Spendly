    Notes for implementation
    Duplicate opens the copy in the edit screen, not saved yet, as 3a step 3 does. Save creates it; Discard, or leaving with a confirm, throws it away. If the copy takes a category over its limit, the edit screen says so as any order does (8b); it never blocks.
    Add files adds files to the copy only.
    8b Budget alerts
    A limit is only useful if it speaks up. Three moments, in order of usefulness: while you are adding the order that crosses it, on the pages that show the category, and once a month as a summary. All of it derives from the limit already on the category - no new settings beyond how loudly to be told.
    Notes for implementation
    Alerts arrive in the app and by email. There are no phone notifications. The switches under How loud live in Settings, in the Limit alerts pane (11a).
    Open statistics opens Statistics (4a) for the month the summary is about, with no crumb: the card names several categories, and the page shows them all.
    A limit is a fact about the month, not a validation rule. Crossing one never disables Save and never routes through the validation layer - keep the check out of that code path entirely, or it eventually starts blocking. Amber informs; red blocks.
    The over-limit chip travels. The same dot renders wherever the category appears - list rows, facet lists and order details - so the state is recognisable without reading the number.
    Attachments do not follow a duplicate because a receipt is evidence of one specific purchase; copying it to another order makes the record lie. Items, vendor, category, reference and notes do carry over.
