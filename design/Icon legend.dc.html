19a Icon legend
Every icon that carries an action, with what it does, where it appears, its tooltip and its accessible name. An icon-only button with no label is unusable with a screen reader and ambiguous with a mouse, so nothing here ships without both columns filled in. Braces are placeholders for the record’s own values.

19b Rules for icons
ONE ICON, ONE MEANING
An icon means the same thing on every screen. The paperclip is always attachments and never "add a file"; the pencil always edits in place and never opens a new page; the plus always appends a row and never opens a dialog. Where two actions feel similar but differ in outcome, they get different icons — which is why Close and Remove-filter are drawn differently despite both being an ×.
A consequence worth stating: if a new action does not map to an icon in 19a, it gets a text button. Inventing a glyph for a one-off is how an icon set stops being learnable.
EVERY ICON-ONLY BUTTON NEEDS BOTH
A tooltip on hover and on keyboard focus, after a 400ms delay, naming the action as a verb.
An aria-label naming the target, not just the verb. "Delete" is useless in a list of nine rows; "Delete Stol — eg" is not. The label is the specific one; the tooltip can stay short because the row is visible.
Decorative icons take aria-hidden="true" and no tooltip. An icon inside a labelled button is decorative — the button already has the name.
DRAWING
16×16 viewBox, stroke only, stroke-width 1.5 for actions and 1.3 for decorative glyphs, round caps and joins, no fills except the drag dots and the filled star.
Rendered at 17px in a 32px button, 15px in a 28px item-line button, 14px inline beside text. Colour is currentColor always, so a row’s hover and disabled states carry the icon with them.
These are drawn for the mockups. Substitute the codebase’s icon set at matching optical weight rather than lifting the paths — what matters is the mapping in 19a, not the geometry.
WHAT NOT TO DO
No icon-only destructive action outside a row. A bare trash icon in a toolbar acting on a selection is too easy to hit — bulk delete is a labelled button.
No icon carrying meaning by colour alone. The amber alert and the red alert are the same glyph; the message beside them is what distinguishes them, and it is always present.
No icon below 28px as a target on desktop, 44px on touch. The glyph can be 14px; the button around it cannot.
No hover-only icons on touch. Anything revealed on row hover is permanently visible below 640px — the item-line pencil is the case that matters.
