19a Icon legend
This table is the register: every icon the interface uses has a row here, and nothing without a row may be used in it. The one exception is a category's icon, which can be any Tabler outline icon, stored by its Tabler name (c7). The only source is Tabler Icons, so the Name column is the Tabler name - adding an icon means finding it in Tabler, adding it to icons.js, and adding its row here, in that order. An icon is never drawn, never edited, and never pasted in from anywhere else. Each row carries what the icon does, where it appears, its tooltip and its accessible name. An icon-only button with no label is unusable with a screen reader and ambiguous with a mouse, so nothing here ships without both columns filled in. Braces are placeholders for the record's own values.

19b Rules for icons
ONE ICON, ONE MEANING
WHAT NOT TO DO
No icon-only destructive action outside a row. A bare trash icon in a toolbar acting on a selection is too easy to hit - bulk delete is a labelled button.
No icon carrying meaning by colour alone. The amber alert and the red alert are the same glyph; the message beside them is what distinguishes them, and it is always present.
No icon below 28px as a target on desktop, 44px on touch. The glyph can be 14px; the button around it cannot.
No hover-only icons on touch. Anything revealed on row hover is permanently visible below 640px - the item-line pencil is the case that matters.
