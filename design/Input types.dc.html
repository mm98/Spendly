14a Component API - the options each control needs
What each control must accept to serve every place it is used in this design, and nothing beyond that. Twenty components. The right-hand column names what drives each option, so an option with nothing behind it can be cut.
Notes for implementation
Every control takes the same five: label, value, onChange, error, disabled - plus id, name and required passed through. Don't re-declare them per component. One shared field wrapper owns the label, the error message and the spacing; each control renders only its own box.
Controlled only. No internal value state, no defaultValue. The order draft is the single source of truth - a control keeping its own copy is how a field silently disagrees with what gets saved.
No variant="danger" on an input. Error is a boolean plus a message, never a visual variant, which makes the red state impossible to apply for decoration.
Resist the extra option. Each row is short on purpose. When a screen needs something not listed, add it here first - that review step is what keeps this at twenty components rather than forty.
COMPONENT
OPTIONS BEYOND THE SHARED FIVE
WHAT DRIVES THEM
TextField
placeholder · maxLength · readOnly · multiline (line cap, then scroll) · prefix / suffix slot · hint
readOnly is the Settings email · multiline is Notes · maxLength is the 64-char reference · prefix carries the category icon inside its name field (5b)
PasswordField
autocomplete (current / new) · meter · hint
Reveal is built in, never optional. meter only on the new-password field. No confirm variant - reveal replaces it. Paste is never blocked
NumberField
decimals (2 for an amount, 3 for a quantity) · min · computed (read-only, tinted) · locale
computed is the line total (1b) and the import total · min 0 blocks negative prices · the separators come from the locale, which comes from Settings and is never hardcoded · the currency is the field's unit slot, not the control's, which is also how a quantity gets no unit at all
Stepper
min · max · step · decimals
Item quantity only. min 1 disables minus rather than deleting the line - there is deliberately no onDelete
Combobox
options · groups (favourites / recent / all - headers non-focusable) · searchable · onCreate · renderOption · multiple · emptyLabel · loading
searchable off is status and formats · omitting onCreate removes the create row, which is how one component serves a closed set · renderOption draws the colour dot, icon tile and order count · multiple is bulk "add category" (2a) · loading is the async vendor list
SearchInput
placeholder · debounce (300ms) · onClear · resultCount
Order list, facet groups over 20 values, the icon picker, the command palette. resultCount goes to a live region - it is what makes the field usable without sight
Segmented
options (2 - 3) · size
rows/cards (2a), row shape (11b), density and theme (11a). A fourth option means it should have been a Combobox
Checkbox
indeterminate · count slot · hitArea (cell / row) · stopPropagation
indeterminate is "select all" over a partial selection · count is the facet number · hitArea is the difference between a table row (the checkbox cell, stopping propagation so a near-miss cannot open the order) and a facet row (the whole row toggles, since it does nothing else) - an 18px target is the single most common cause of the wrong action firing on touch
Radio
options · meta slot per option · rowTarget
Bulk "set status" (2a) and the date presets (2d) - a single value from a set too long or too annotated for Segmented. meta is the right-aligned count beside each option. Not for two options: that is Segmented
Toggle
description
All it needs. No size, no colour, no loading state - a toggle that can be pending is not a toggle
DateField
min / max · shortcuts · range · format
max today blocks future order dates · shortcuts are Today / Yesterday · range is the Statistics custom period · format comes from Settings; a week starts on Monday
FileDrop
accept · maxSize · multiple · files with per-file progress and error · onRetry · onRemove · compact
Three sizes of one thing: the Home capture zone, the order attachment strip (compact), and the import picker. No capture attribute: the device's own picker offers the camera beside the library. Per-file error is what keeps a failed upload on screen instead of vanishing
SwatchPicker
items · searchable · overflowAfter · custom (colour only)
One component for colour and icon. items are the suggested values shown first, not the permitted ones - custom adds the box that opens the system colour picker, so any colour can be chosen. Columns come from the width it is given, never passed in. Two-dimensional arrow keys; every item needs an accessible name
Button
level (primary / secondary / ghost / destructive) · size · icon · iconOnly · loading · as · fullWidth
as="a" keeps cmd-click working on anything that navigates · iconOnly requires an aria-label · loading holds the width and blocks a second submit · fullWidth only in a mobile sheet · destructive is reachable only inside a Dialog
RangeSlider
min / max · step · value as a pair · format
Used once, in the amount facet, and never on its own - always above the two NumberFields it mirrors. Both directions bind to the same state
SortControl
options · value · onChange
A Combobox in pick-only mode with a persistent "Sort" prefix - not a separate component. Listed here because it renders at radius 10px, the one control that does
Pager
page · pageSize · total · sizes
Renders the range sentence, the size Combobox and the two arrows. Total is the filtered total, never the account total
Chip
tone (accent / neutral / amber) · icon · count · selected · onRemove · onClick
Four roles from one component: onRemove is an active-filter chip, selected + count a facet chip (rendered as a hidden checkbox in a fieldset), onClick alone a date shortcut, neither a status pill. Never onRemove and selected together - output and input in one chip
DrillCrumb
label · mark · isLast · onTruncate · onRemove
Statistics only. isLast switches the fill and reveals the ×; earlier crumbs get onTruncate instead. mark renders an IdentityMark inline. Not a Chip - different shape, different meaning, never in the same row
IdentityMark
kind (person / vendor / category) · name · size (inline 24 / row 42 / form 64) · icon and colour, category only
Initials and colour are derived inside the component from the canonical name, never passed in - that is what keeps one vendor looking the same in every list. Category is the exception: the user chose its icon and colour, so they are stored on the record as the values they are - any colour, not an index into a palette. Full rules in c2.
THE SHARED FIELD WRAPPER
One component above all of them, owning what every field has in common. Build this first - it is the reason none of the controls below carry a label prop of their own.
Order date
the control renders only this box
hint, or the error message, in the same slot
It owns: the label and its htmlFor, the required marker, the hint/error slot and its aria-describedby, aria-invalid, and the 5px label gap. Error and hint share one slot so a field never grows when it fails - the row height is identical in both states, which is what stops a form jumping as you tab through it.
WHAT IS NOT A COMPONENT HERE
Radio group with two options. Two mutually exclusive choices are a Segmented, always. Radio starts at three, and only when the options carry meta or wrap - otherwise Segmented still wins.
A standalone slider. The one range control is the amount facet, and it is a RangeSlider paired with two NumberFields - see c3. A slider alone is never enough, because a receipt total is usually typed.
Autocomplete, tag input, rich text, native select. All are the Combobox, the Chip list, the multiline TextField, or nothing. Each would be a second implementation of something already here, and the second one is always the one that misses the keyboard support.
Form. No form component. Screens compose the wrapper and the controls directly, because each screen's save behaviour differs - per card in Settings, one sticky bar on order edit, a staged dry run in import.
BUILD ORDER
1. The field wrapper, then TextField (PasswordField is the same field plus a reveal) and Button - between them they unblock every screen.
2. Combobox. The largest piece by a distance, and four screens are waiting on it. Do the keyboard table in c9 before the styling, not after.
3. NumberField and Stepper, together - they share the parsing and formatting.
4. Checkbox, Segmented, Chip, SearchInput. Small, and the order list needs all four at once.
5. IdentityMark, SortControl and Pager - small, and the vendors library and order list need all three.
6. FileDrop, DateField, SwatchPicker, Toggle.
7. RangeSlider, last - it is used once, in the amount facet, and only alongside the NumberFields from step 3.
Each one lands with its states from this page as the acceptance criteria - default, filled, focus, error, read-only, disabled, loading where it applies. A control shipped without its error state gets that state invented three times later, differently.
