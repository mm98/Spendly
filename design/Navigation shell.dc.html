9a Navigation shell
One frame around every area. The sidebar holds the areas and never scrolls away; the top bar is the locked shell we cannot put actions in, so it carries identity, search and the two global actions only. Everything a page does lives inside the page, as in the edit and list screens.
NOTE ON THE FRAME
The rounded corners, the 1px outline and the drop shadow around the shell below are presentation only — they exist so the mockup reads as a window on this page. In the app the shell fills the browser viewport edge to edge: the sidebar runs the full height with square corners, and the content column meets the window edge with no border and no radius. Same for the fixed 1400px width, which stands in for a viewport.

NOTES FOR IMPLEMENTATION
Why each row exists. The header repeats the email, which appears nowhere else in the shell and is how you confirm which account you are in. Account and profile deep-links to that section of Settings rather than duplicating it — the nav's Settings row goes to the page top. Keyboard shortcuts opens the shortcut sheet, and this is its only entry point besides pressing ?. Sign out is the reason the menu exists at all: it is the one action that should not be buried in a settings page.
Where "Account and profile" goes. Not a new screen — it is Settings (11a) at /settings/account, whose first card is already that form: avatar with upload and remove, name, read-only email, and Change password. The only difference from the nav's Settings row is arrival state: the section is selected in the left nav, the page is scrolled to that card, and focus lands on the card's heading so a keyboard user knows where they arrived. No highlight flash, no auto-focused field — nothing is being asked for yet.
Deliberately not here. No theme switch — the toggle sits directly above in the sidebar, and two controls for one preference is how they drift. No org or account switching, because there is one user. No "Upgrade".
Anchoring. Opens upward, aligned to the block's left edge, 232px wide, radius 12px, shadow 0 6px 16px rgba(27,26,23,0.08), 4px above the trigger. Light surface, like every other popover — it belongs to the page, not to the sidebar.
The chevron indicates state: down when closed, up when open. It is the only thing on the block that changes.
Behaviour. Standard menu semantics — aria-haspopup="menu" and aria-expanded on the block, role="menu" on the panel, arrow keys between items, Esc closes and returns focus to the trigger, click outside closes. Sign out confirms only if there are unsaved changes, naming what would be lost.
Collapsed rail. The block becomes the avatar alone and the chevron disappears; the same menu opens to the right of it.

WHAT IS NOT IN IT
Anything destructive. No delete, no merge, no undo. A palette is typed fast and confirmed by reflex; it is the wrong surface for something irreversible.
Anything that acts on the current page. No "save this order", no "add a line". Page actions live on the page, and a command whose meaning depends on what is behind the overlay is unpredictable.
Settings values. Theme is there because it is a single reversible switch. Currency, defaults and statuses are not — they belong in a form where the consequence is visible.
A command for everything. The list above is nine entries and should stay near that. A palette that lists every action becomes a menu with worse ergonomics.
BEHAVIOUR
560px, centred, top-anchored at 15vh. Radius 14px, shadow 0 14px 32px rgba(27,26,23,0.14), scrim rgba(27,26,23,0.35). It does not grow past 60vh; the result list scrolls inside it.
Groups are fixed in order — Orders, Vendors, Items, Actions — and a group with no matches is hidden entirely, header included. Each shows at most three rows plus "See all N in …".
Arrows traverse everything as one list, crossing group boundaries and skipping headers. Same rule as the combobox in 14a — build the flat list, render headers into it.
Actions rank above records only when the query matches a command name. Typing a vendor name should never put "Switch to dark mode" first.
Search is debounced 300ms and cancels in flight. The previous results stay visible while the next load runs — the list never blanks between keystrokes.
Matched text is highlighted in amber, including mid-word, since Danish compounds mean the match is often not at the start.
Vendor aliases are searched (5d). A row matched on an alias shows the canonical name followed by "— matched indbo.dk" in muted 12px, or the result looks like it does not contain the query.
No results is one line — "No matches for møb" — plus "Search all orders", which leaves the palette for the list with the query applied.
Opening from the order list carries the query into the field, so ⌘K from a filtered list continues rather than restarts.
Unsaved changes prompt before it navigates, the same as any other navigation.
Not on mobile. Below 640px ⌘K has no meaning and the search field goes to the order list instead.
JUMP BACK IN
The empty state lists the last five records opened, newest first, mixing orders and vendors. Stored locally per user, not on the server — it is a convenience, not data.
A deleted record drops out silently rather than showing a broken row. With no history the group is hidden and Actions moves up; the palette never shows an empty group with a caption explaining that it is empty.
