6d Confirmations
Reversible things get a toast with Undo and no dialog. A dialog appears only when the effect reaches beyond what you can see — deleting an order with attachments, merging two vendors, discarding a scan. Each one names the consequence in numbers and puts the destructive verb on the button, never “OK”. Every specimen below is labelled with the surface it is, because two of them are easy to mistake for a third: the offline message is a toast that carries no Undo, and the two-tab conflict is a section notice rather than a toast, since it has to stay until it is answered. 6f is the rule for choosing between them.

6f Which surface, and when
The pages above draw each surface but never say how to choose between them. Five surfaces, and the choice comes down to two questions: does the message belong to one field or to the whole action, and must the user answer it before anything continues.

WHICH ONES, HERE
Inline
Vendor is required
The message belongs to one field and the user is already looking at it. Never shifts the layout — error and hint share one slot, so the row height is the same either way.
Field validation (6c) · the amber over-limit notice (8b) · uncertain scan fields (3a) · the duplicate-name warning (16c) · per-file upload errors (17b)
Section notice
Copied from 12 Aug
The message is about the whole screen's state rather than one field, and has to stay visible while the user works. Top of the content column, and it scrolls with the page.
The duplicate notice (8a) · scan failed (6e) · totals reconciliation in review (3a) · the monthly over-limit summary on Home (8b)
Popover
Set status ▾
The user needs to choose something, anchored to what they clicked. It takes nothing away, so Esc or a click outside just closes it. Never carries a message — only choices.
Set status and Add category (2a) · Export (16c) · the account menu (9c) · every combobox panel · the icon picker (5b)
Dialog
Delete this order?
The action cannot be undone, or the user must answer before anything continues. Modal, focus-trapped, scrim behind. If it can be undone, this is the wrong surface.
Delete order · bulk delete · vendor merge · discard scan · leave-while-dirty · change password (16c) · see-theirs conflict (16c)
Toast
Line removedUndo
It already happened and can be undone. Confirms rather than asks, so it never blocks and never needs acknowledging. One at a time, bottom-centre, 6s.
Line delete · status change · category add · archive (16c) · import complete · order saved
THE TEST, IN ORDER
1
Is it about one field? Inline. This catches most messages in the app.
2
Has it already happened? Toast if it can be undone. Section notice if it cannot and the user needs to keep seeing it.
3
Is the user picking from a set? Popover, anchored to the trigger.
4
Would proceeding lose something? Dialog. Only here.
If two answers fit, take the earliest — the order runs from least interrupting to most.
NEVER
A toast for an error the user must fix. It disappears, taking the only description of the problem with it. Errors are inline, next to their cause.
A dialog for something reversible. It taxes every use to prevent a cheap mistake. Undo taxes only the mistakes.
Both surfaces for one action. A dialog followed by a toast means it was confirmed twice; the dialog closing is the confirmation.
A popover carrying a message. If there is nothing to choose, it is a notice or a toast.
A toast for a limit being crossed. That is a fact about the month, not an event — inline, amber, and it stays.
WHEN THEY STACK
Esc closes the topmost layer only, in this order: sheet, dialog, popover, inline edit. A dialog opened from a popover closes the popover first.
Toasts sit above everything and are never blocked by a dialog — a background action finishing must not be swallowed by whatever is open in front of it.
Only one dialog at a time. A dialog that needs to open another means the first asked the wrong question.
