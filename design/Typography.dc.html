LOADING, AND FALLING BACK
Stack
Poppins, system-ui, sans-serif
Weights 400, 500, 600 and 700, latin and latin-ext. Nothing else — no italics anywhere in the interface, and no 300 or 800. If a weight is missing, the browser synthesises it and the amounts stop lining up.
Self-host the four weights rather than calling Google Fonts. The mockups use the CDN for convenience; a receipt tracker shouldn't need a third party to render a total. font-display: swap, and preload the 400 and 600 files — those two carry almost every screen.

TRUNCATION AND OVERFLOW
Vendor names, item names and filenames are user data and can be any length. Every one of them sits in a cell that must not grow. The rule is per role, not per component — decide once what each role does when the text is too long.

A flex child's automatic minimum size stops it shrinking below its content, so the ellipsis never fires and the amount gets pushed out of the row. The catch is which element needs the fix: min-width: 0 belongs on the flex child — usually the wrapper holding the name and its meta line — not on the truncating text itself, which already escapes the rule by having overflow: hidden. Two levels of wrapper means two declarations. Grid cells need the same treatment. This is the most common cause of a row overflowing on mobile.
Test every list with a 60-character vendor name and a 120-character item name. Both exist in real receipts, and a layout that only holds for "Hay" isn't finished. overflow-wrap: anywhere on notes and references, which can be one unbroken string.
RULES
Nothing below 10px. 10px is the sidebar label only. 11px is the floor for anything a user reads, and it is always uppercase or muted.
Letter-spacing only goes up, and only on uppercase. 0.12em at 11px, 0.14em at 10px, 0.08em on table headers. Never negative, at any size.
Line-height follows length. 1.15 for titles, 1.5–1.55 for anything over one line, 1 for figures standing alone. Add text-wrap: pretty to every heading and paragraph.
Weight carries emphasis, not colour. 600 is the strongest thing in a row. Bold plus a colour change on the same word is doubling up.
Mobile keeps these sizes. The phone layout drops fields rather than shrinking type. Row primaries go up to 15px, nothing goes down.
On dark, drop one step of weight where you can. Light text on a dark surface reads heavier than the reverse: a 600 row primary at 14px holds, but 700 at 28px can go to 600 without losing the hierarchy.
