SPENDLY · DESIGN MOCKUPS

Order tracking for personal receipts, from capture to what it all added up to.

Seventeen files, forty-three screens. It started with one problem — the order header took too much room above the items — and grew into the flows around it: the list, creating from a scanned receipt, statistics, vendors and categories, the states in between, and the phone.

Every screen carries a visible id badge, unique across the whole set, so it can be pointed at in review.

RULES EVERY SCREEN FOLLOWS
The top shell is locked
No page actions live up there. Everything a page does belongs to the page.
A limit never blocks a save
Red blocks, amber informs. A monthly limit is a fact about your month, not a rule.
Nothing saves by itself
Scans propose, they never overwrite. A duplicate opens unsaved and can still be abandoned.
Numbers answer the current filter
Totals and counts reflect what is on screen, not the whole account.
Single user, personal receipts
No item catalogue, no shared editing, no permissions. A conflict means two tabs, not two people.

These are design references, not production code: layout and states only, no data or behaviour. Where a mockup and the code disagree, the code is the current truth — the mockup is the proposal.
