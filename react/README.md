# Spendly, the web app

React on the Spendly API (`../api`). Every page reads and writes real records through it.

```bash
npm install
npm run dev            # http://localhost:5173, proxies /api to http://localhost:4000
npm run build          # dist/, then .gz and .br beside every text file
npm run design:check   # the design system's rules, held against src/ (runs in CI)
npm run bank:check     # the bank statement reader against scripts/fixtures
```

The API has to run beside the dev server (`npm run dev` in `../api`), or every page shows its
error state. `SPENDLY_API_URL` points the proxy somewhere else.

## What is here

```
src/
  main.jsx        mounts the router; loads fonts, tokens, components and the page layout files
  routes.jsx      every route, its page (lazy) and its handle
  app/            the shell around the pages: sidebar, top bar, tab bar, palette, theme,
                  sign-out, shared order row parts
  components/     the design system's components, one file per family, plus icons.js (the
                  interface's icons) and tabler/ (the whole Tabler library a category's icon is
                  picked from, generated by `npm run icons:sync`, loaded a part at a time)
  pages/          one module per screen
  api/            client.js (every request), useApi.js (the read cache), format.js (money,
                  dates, counts in the account's own format), the bank statement reader
  styles/         tokens.css, components.css, app.css, fonts.css, and pages/ (one layout file per screen)
  fonts/          Poppins 400, 500, 600 and 700
public/           icons, the web manifest, theme.js (sets the theme before the first paint)
scripts/          check-design, check-bank-statement, sync-icons, precompress, regen-docs, lighthouse
```

## The design system

The design handoff is `../design`. Two parts of it are lifted into the app, not redrawn:

- `design/styles/tokens.css` and `components.css` are `src/styles/tokens.css` and
  `components.css`, byte for byte: `check-design` fails when they differ. Every value is a
  token; every look is a component rule there.
- `src/styles/app.css` holds what the app adds to them, and nothing else: the drawn screens
  placed in a real window (pinned bars, `100dvh`, scroll room), the rules for what a design note
  states in words but has no CSS for yet, and the few places where the design's own stylesheet
  does not give what its drawing shows. Each rule names the design section it implements.
- `design/react_handoff/*.jsx` are the components in `src/components/`, in the same files.
  Components the screens needed and the handoff did not ship are added beside them, copied from
  the canonical markup in `design/Components.dc.html`.

Pages are built only from those components. A component takes closed, named props (an unknown
variant value is reported, never passed through as a class); colour rides in `data-color`; no
`className` or `style` reaches a library component. A screen's own layout (a two-column split,
a sticky year sheet) is a page layout file in `src/styles/pages/`, ported from the matching file
in `design/styles/pages/`, wrapped in `@layer base` so a component rule always wins.

`scripts/check-design.mjs` holds these as assertions: classes resolve, tokens are defined,
spacing only from the scale, variant sets closed, no `className` or `style` on a library
component, page layout files in `@layer base` with no component class and no raw spacing, a
saving written as an amount, no typographic dashes or curly quotes, and Bookmarks never called
a wishlist.

## Routes

| Route | Screen |
| --- | --- |
| `/` | Home |
| `/orders` | Order list; filters, sort and search live in the address |
| `/orders/new` | New order: blank, from a receipt (`?source=scan`), or a copy (`?duplicate=<id>`) |
| `/orders/:id`, `/orders/:id/edit` | One order, and its edit form |
| `/statistics` | Statistics by week, month, quarter or year |
| `/vendors`, `/categories`, `/bookmarks` | The three libraries, each with `/new` and `/:id/edit` |
| `/budget`, `/budget/:year` | The yearly budget |
| `/budget/check` | Check a bank statement against the budget |
| `/ask` | Ask: questions about the account, while the server has an assistant set up |
| `/settings`, `/settings/:section` | Settings, import, demo data, this build |
| `/more` | The phone's list of what the tab bar does not hold |
| `/more/views` | Saved order views |
| `/signin`, `/register`, `/welcome`, `/confirm`, `/reset`, `/terms`, `/privacy` | Outside the shell: sign in, create an account, first run, the links in emails, and the notices |

The category list also reads two filters from the address, with no control on the page: `flag=over-limit`
keeps the categories past their limit, and `month=2026-10` keeps those with spend in that month and shows
every figure for it. Each shows as a crumb above the list, and they combine.

The router is a hash router (`#/orders`), so a built copy opens from any path or a `file://`
URL. Each route's `handle` carries the browser tab's title, the sidebar row it belongs to, the
body layout (`default`, `split` or `rail`) and whether the phone shows the New order button.
Pages draw no heading and no back button: the shell names the page.

**Every link into the app from outside it is `/open/<route>`**: an email, a notice, anything sent
or shared that opens a page. It carries no `#`, as a mail program or its link checker can drop
everything after one. The server answers `/open/categories` with a redirect to `/#/categories`, the
query kept. Build such a link with `linkTo` or `publicLink` in `api/src/lib/mail.js`, never by hand
and never another way. The dev server and `vite preview` pass `/open` on to the API, so the links
work locally too.

## The shell

Three shapes, chosen by window width in `app/useMedia.js`:

- 1280 and up: the full sidebar.
- 640 to 1279: the icon rail. A `rail` layout (the order list's facets) becomes the default
  body here, and the facets move to a sheet.
- Below 640: touch. A tab bar (Home, Orders, Statistics, More), the New order button on Home
  and Orders, and `sp-touch` on the body so sheets and dialogs opened over the page get touch
  sizes too.

The page stays mounted when the window crosses a breakpoint, so a rotated phone keeps unsaved
work. The split body (a form beside its rail) folds to one column at a 900px content width, in
CSS.

## Data

`api/client.js` is the only place that calls `fetch`. `useApi(fn, args)` is the only read path:
it caches by function and arguments, and `invalidate()` tells every mounted reader of a stale
answer to fetch again, so a sidebar count follows a write on another page. Signing out clears
the cache without asking the readers on screen to fetch again. A request refused because the
session has ended opens the "You've been signed out" dialog.

## The build

Every page is its own chunk, loaded when its route is first opened. React, the DOM renderer and
the router are one `vendor` chunk, so an edit to a page leaves them cached. `npm run build` prints
the current sizes.

- `scripts/precompress.mjs` writes `.gz` and `.br` beside every text file; the API serves the
  smallest one the browser accepts.
- No source maps. A stack trace is read against the commit `/api/version` names.
- The four Poppins faces are preloaded from `index.html`, so they load with the stylesheet
  rather than after it.
- `public/theme.js` runs before the first paint and sets the theme, so a dark reader never sees
  a light frame. It is a file, not inline code, because the API's security policy runs no inline
  script.

## Lighthouse

`node scripts/lighthouse.mjs <url>` scores a served build (`npm run build`, then
`node api/src/server.js` over `react/dist`), never the dev server. It runs twice and prints both.
Not re-run since the redesign. The CI job and the scoring of the built image are switched off
(`if: false` in `.github/workflows`); nothing in the app shows the score, so the image answers
"never measured".
